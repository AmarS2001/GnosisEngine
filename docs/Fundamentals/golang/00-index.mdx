# 🧭 Golang (Go) — Overview & Curriculum Map

## 🎯 What Problem Go Solves

Go was created at Google by **Rob Pike**, **Ken Thompson**, and **Robert Griesemer** to solve a specific set of software engineering pain points in massive, multi-threaded C++ and Java codebases:
1. **Compilation Latency**: Eliminating long build times with a single-pass compiler and strict dependency resolution.
2. **Uncontrolled Concurrency Complexity**: Replacing manual OS thread management, mutex locks, and callbacks with built-in **Communicating Sequential Processes (CSP)** concurrency (Goroutines and Channels).
3. **Over-Engineered Type Hierarchies**: Replacing classical class-based inheritance and brittle virtual method tables with **implicit structural interfaces** and composition.
4. **Deployment Friction**: Eliminating dynamic link/runtime dependency hell by producing statically linked, zero-dependency single binaries with ultra-fast startup times.

Go trades compiler magic and deep meta-programming abstractions for **simplicity, readability, runtime performance, and massive developer velocity**.

## 📋 Assumed Background

This curriculum assumes you are a **senior software engineer** with strong foundations in:
- General Computer Science principles (data structures, algorithms, memory layout, stacks, heaps, pointers).
- Multi-threading concepts (CPU scheduling, race conditions, atomic operations, lock contention).
- Basic networking and OS fundamentals (syscalls, file descriptors, sockets, epoll/kqueue).

You do **not** need any prior experience with Go syntax, the Go runtime (GMP), or Go tooling.

## 📖 Core Glossary

| Term | Definition |
|---|---|
| **Goroutine** | A lightweight user-space green thread managed by the Go runtime, starting with a 2 KB growable stack. |
| **Channel** | A thread-safe FIFO queue used for communication and synchronization between goroutines. |
| **CSP** | Communicating Sequential Processes — a formal model of concurrency where processes interact via message passing. |
| **GMP Scheduler** | The Go runtime's M:N scheduler matching **G**oroutines to OS Threads (**M**) via Processor contexts (**P**). |
| **Escape Analysis** | Compiler analysis that determines whether a variable can be safely allocated on the stack or must escape to the heap. |
| **Slice Header** | A 24-byte structure (`reflect.SliceHeader`) containing a pointer to a backing array, `len`, and `cap`. |
| **`iface` / `eface`** | Internal runtime representations of interfaces: `iface` (interface with methods: `itab` + data) and `eface` (`any` / empty interface: `_type` + data). |
| **Tri-Color GC** | A concurrent mark-and-sweep garbage collection algorithm operating with White, Grey, and Black object states. |
| **Zero Value** | Default value assigned automatically to uninitialized variables (e.g., `0`, `""`, `false`, `nil`). |
| **Go Module** | A collection of Go packages stored in a file tree with a `go.mod` file defining version requirements. |
